# Contributing to Play-2048

Thanks for your interest in contributing to Play-2048!

The project is small and focused; to keep contributions clear and quick to review, please follow the guidelines below.

## How to contribute

1. Fork the repository and create a branch from `main`:
   - `git checkout -b feat/short-description`
2. Make your changes and add clear tests (where applicable).
3. Run any linters or tests locally.
4. Commit with a clear message and push the branch to your fork.
5. Open a Pull Request against `main` that explains:
   - what you changed
   - why the change is needed
   - how to validate it locally

## Issues

- Search existing issues before opening a new issue.
- For bug reports include:
  - Steps to reproduce
  - Expected vs actual behavior
  - Browser and OS used
  - Any console logs or screenshots

For feature requests, explain the use case and possible UX.

## Pull request checklist

- [ ] Branch name follows convention
- [ ] Tests added/updated (if applicable)
- [ ] Code formatted and linted
- [ ] Documentation updated (README, docs/)
- [ ] PR description explains why and how

## Coding style

- Keep the code simple and readable.
- Prefer plain JavaScript (ES6+) for game logic.
- If the repository uses a specific linter (ESLint) or formatter (Prettier), follow that configuration.

## Communication

- Use GitHub Issues for questions, bugs, and feature requests.
- Mention maintainers in PRs for review if needed.
